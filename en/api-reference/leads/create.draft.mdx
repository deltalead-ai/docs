<Note>
  The REST API is in early access and is enabled per account on request. API keys are not yet issued from the dashboard. To request access, contact your account executive.
</Note>

Create a lead in DeltaLead without the contact having to arrive through a connected channel. Use it to import contacts from a legacy database, push submissions from your own form, or forward leads from a third-party source that isn't natively integrated. The lead appears in the unified inbox as soon as it is created.

## Endpoint

```text
POST https://platform-api.deltalead.ai/v1/leads
```

## Request Body

<ParamField body="contact" type="object" required>
  Contact details for the person. It is a nested object — neither the name nor the phone number is sent at the root of the lead.
</ParamField>

<ParamField body="contact.first_name" type="string">
  Given name.
</ParamField>

<ParamField body="contact.last_name" type="string">
  Family name.
</ParamField>

<ParamField body="contact.email" type="string">
  Email address.
</ParamField>

<ParamField body="contact.phone" type="string">
  Phone number. [E.164 format](https://en.wikipedia.org/wiki/E.164) is recommended, e.g. `+5491155551234`.
</ParamField>

<ParamField body="contact.display_name" type="string">
  Display name. If omitted, DeltaLead composes it from `first_name` and `last_name`.
</ParamField>

<ParamField body="status" type="string" default="new">
  Initial status of the lead. Closed enum: `new`, `contacted`, `qualified`, `appointment`, `proposal`, `incubating`, `won`, `lost`.
</ParamField>

<ParamField body="score" type="integer">
  Qualification score, an integer from `0` to `100`. If omitted, the lead stays unscored until the AI evaluates it.
</ParamField>

<ParamField body="interested_vehicles" type="array of string">
  Catalogue vehicle IDs, not free text. A vehicle that is not in the catalogue has to be added there first and then referenced by its ID.
</ParamField>

<ParamField body="notes" type="array of object">
  Notes on the lead. Each element is an object and `body` alone is enough; DeltaLead fills in the rest of the note's fields.
</ParamField>

<ParamField body="notes[].body" type="string" required>
  Note text. Visible to your team and never sent to the lead.
</ParamField>

### Validation rules

There are two, and they are the only ones:

1. At least one of `contact.first_name` or `contact.last_name`.
2. At least one of `contact.email` or `contact.phone`.

If either condition is missing, the response is `422` and no lead is created.

## Example Request

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/leads \
  -H "Authorization: Bearer dl_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contact": {
      "first_name": "María",
      "last_name": "García",
      "email": "maria@example.com",
      "phone": "+5491155551234"
    },
    "status": "new",
    "score": 40,
    "interested_vehicles": ["veh_9f2c41"],
    "notes": [
      {"body": "Consultó por financiación a 36 cuotas."}
    ]
  }'
```

## Response

A successful request returns HTTP `201 Created` with the newly created lead. See [Get Lead](/en/api-reference/leads/get) for the field-by-field description.

A lead created through the API has no channel: `channels` starts empty and fills in as the person talks over WhatsApp, MercadoLibre, email, or another channel. `ai_summary_status` starts at `not_requested`.

## Errors

<Accordion title="422 — Validation">
  Returned when the body does not satisfy one of the two validation rules. The `errors` array names the field that failed.

  ```json 422 Unprocessable Entity
  {
    "status": "error",
    "detail": "validation_error",
    "errors": [
      {
        "field": "contact",
        "detail": "email_or_phone_required"
      }
    ]
  }
  ```

  Branch on the `detail` identifier, never on the text. The full list of codes is in [Errors](/en/api-reference/errors).
</Accordion>
