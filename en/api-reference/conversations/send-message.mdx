<Note>
  The REST API is in early access and is enabled per account on request. API keys are not yet issued from the dashboard. To request access, contact your account executive.
</Note>

Send a message into an active conversation on behalf of a person on your team, with no involvement from the AI agent. This is the right call when a seller needs to step in at a critical moment — discussing financing, handling a price negotiation, or closing a deal — without waiting for the AI to respond first.

Sending is asynchronous. The API responds `202 Accepted` once the message is queued toward the channel, not once the recipient receives it: delivery is tracked afterwards through the message's `status` field.

## Endpoint

```text
POST https://platform-api.deltalead.ai/v1/conversations/{id}/messages
```

## Path parameters

<ParamField path="id" type="string" required>
  The unique identifier of the conversation to send the message into, e.g. `conv_xyz789`. The conversation must not be `resolved`.
</ParamField>

## Request body

<ParamField body="body" type="string" required>
  Text body of the message. Must be a non-empty string, except when the message carries an attachment. Markdown formatting is not rendered on the recipient's device — send plain text.
</ParamField>

<ParamField body="type" type="string" default="text">
  Message type. Accepted values: `text`, `image`, `document`. Defaults to `text`.
</ParamField>

<ParamField body="media_url" type="string">
  Publicly accessible URL of the file to attach. Required when `type` is `image` or `document`, and ignored when `type` is `text`.
</ParamField>

## Example request

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/conversations/conv_xyz789/messages \
  -H "Authorization: Bearer dl_live_..." \
  -H "Content-Type: application/json" \
  -d '{"body": "Hi María, I'\''m your sales advisor. Let me check the financing options for you."}'
```

## Response

A successful request returns `202 Accepted` with the message created and queued. The message starts with `status` set to `queued`.

```json 202 Accepted
{
  "id": "msg_005",
  "conversation_id": "conv_xyz789",
  "direction": "outbound",
  "body": "Hi María, I'm your sales advisor. Let me check the financing options for you.",
  "type": "text",
  "media": [],
  "sender": "human",
  "ai_agent_id": null,
  "ai_agent_name": null,
  "status": "queued",
  "error_code": null,
  "received_at": null,
  "created_at": "2024-03-11T09:05:33Z",
  "updated_at": "2024-03-11T09:05:33Z"
}
```

### Response fields

<ResponseField name="id" type="string">
  Unique identifier of the newly created message, prefixed with `msg_`.
</ResponseField>

<ResponseField name="conversation_id" type="string">
  ID of the conversation the message was sent into.
</ResponseField>

<ResponseField name="direction" type="string">
  Always `outbound` for messages sent through this endpoint.
</ResponseField>

<ResponseField name="body" type="string">
  The message text exactly as sent.
</ResponseField>

<ResponseField name="type" type="string">
  Message type, as specified in the request. One of `text`, `image`, `document`.
</ResponseField>

<ResponseField name="media" type="array">
  Files attached to the message. An empty array on text messages.
</ResponseField>

<ResponseField name="sender" type="string">
  Always `human` for messages sent through this endpoint, which distinguishes them from AI agent messages in the history.
</ResponseField>

<ResponseField name="ai_agent_id" type="string | null">
  Always `null` for messages sent through this endpoint.
</ResponseField>

<ResponseField name="ai_agent_name" type="string | null">
  Always `null` for messages sent through this endpoint.
</ResponseField>

<ResponseField name="status" type="string">
  Delivery status. Starts at `queued` and moves to `sent`, `delivered`, or `failed`.
</ResponseField>

<ResponseField name="error_code" type="string | null">
  Identifier of the failure reason, in `snake_case`. Only populated when `status` is `failed`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the message was queued.
</ResponseField>

<Note>
  `202 Accepted` confirms that DeltaLead accepted the message, not that the lead received it. The channel can still reject it later — if the WhatsApp messaging window has closed, for example — and the message then ends up `failed` with an `error_code`. Check the final state by re-reading the conversation with [Get conversation](/en/api-reference/conversations/get).
</Note>

## Hand the conversation to a person

`handoff` takes the conversation away from the AI agent and assigns it to a seller. While the conversation is `handed_off`, the AI agent stops replying: only the assigned person answers.

```text
POST https://platform-api.deltalead.ai/v1/conversations/{id}/handoff
```

<ParamField body="assignee" type="string">
  ID of the person taking over. If omitted, the conversation is assigned according to your organization's handoff rules.
</ParamField>

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/conversations/conv_xyz789/handoff \
  -H "Authorization: Bearer dl_live_..." \
  -H "Content-Type: application/json" \
  -d '{"assignee": "user_xyz789"}'
```

Returns `200 OK` with the updated conversation, without the `messages` array.

```json 200 OK
{
  "id": "conv_xyz789",
  "organization_id": "org_xyz789",
  "lead_id": "lead_abc123",
  "status": "handed_off",
  "assignee": "user_xyz789",
  "unread_count": 0,
  "last_inbound_at": "2024-03-11T09:04:58Z",
  "last_message_at": "2024-03-11T09:05:33Z"
}
```

## Resolve the conversation

`resolve` closes the conversation: it becomes `resolved` and drops out of the threads that need attention. A later inbound message from the lead reopens it as `open`.

```text
POST https://platform-api.deltalead.ai/v1/conversations/{id}/resolve
```

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/conversations/conv_xyz789/resolve \
  -H "Authorization: Bearer dl_live_..."
```

Returns `200 OK` with the updated conversation, in the same shape as `handoff`.

```json 200 OK
{
  "id": "conv_xyz789",
  "organization_id": "org_xyz789",
  "lead_id": "lead_abc123",
  "status": "resolved",
  "assignee": "user_xyz789",
  "unread_count": 0,
  "last_inbound_at": "2024-03-11T09:04:58Z",
  "last_message_at": "2024-03-11T09:05:33Z"
}
```
