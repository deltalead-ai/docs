<Note>
  La API REST está en acceso anticipado y se habilita por cuenta a pedido. Las claves de API no se emiten todavía desde el panel. Para solicitar acceso, contactar al ejecutivo de cuenta.
</Note>

Cada solicitud a `https://platform-api.deltalead.ai/v1` lleva una clave en la cabecera `Authorization`. Sin ella, la solicitud se rechaza antes de cualquier procesamiento. No hay cookies, sesiones ni flujos OAuth para el acceso servidor a servidor: alcanza con una clave bearer válida.

La clave también determina el modo. Una clave `dl_live_` crea leads reales; una `dl_sandbox_` escribe en un almacén aislado que nunca llega al Inbox unificado y se purga solo. Nada más de la solicitud cambia entre una y otra, así que la misma integración se verifica contra sandbox y después se promueve cambiando la clave.

## Obtener una clave

<Steps>
  <Step title="Abrir la pantalla de integraciones">
    En el panel de DeltaLead, ir a **Organización → Integraciones → Custom Webhooks**.
  </Step>
  <Step title="Crear la clave">
    Elegir producción o sandbox, ponerle un nombre descriptivo —`production-crm-sync`, `dev-testing`— y, opcionalmente, un vencimiento de entre 1 y 365 días.
  </Step>
  <Step title="Copiarla y guardarla">
    Copiar la clave antes de cerrar el diálogo y guardarla en un gestor de secretos como AWS Secrets Manager o HashiCorp Vault.
  </Step>
</Steps>

<Warning>
  La clave se muestra **una sola vez**, al crearla. Solo se guarda un hash, así que una clave perdida no se recupera: se rota. Nunca conviene dejarlas en el código fuente, en archivos `.env` versionados ni en documentos de texto plano.
</Warning>

## Enviar la clave

```bash
curl https://platform-api.deltalead.ai/v1/leads \
  -H "Authorization: Bearer dl_live_YOUR_KEY"
```

`dl_live_YOUR_KEY` se reemplaza por la clave copiada del panel. El esquema se compara sin distinguir mayúsculas y el token se recorta.

La misma solicitud desde clientes HTTP habituales:

<CodeGroup>

```python Python
import httpx

client = httpx.Client(headers={"Authorization": "Bearer dl_live_YOUR_KEY"})
response = client.get("https://platform-api.deltalead.ai/v1/leads")
print(response.json())
```

```javascript Node.js
const response = await fetch("https://platform-api.deltalead.ai/v1/leads", {
  headers: {
    Authorization: "Bearer dl_live_YOUR_KEY",
  },
});
const data = await response.json();
console.log(data);
```

```php PHP
$ch = curl_init("https://platform-api.deltalead.ai/v1/leads");
curl_setopt($ch, CURLOPT_HTTPHEADER, ["Authorization: Bearer dl_live_YOUR_KEY"]);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
$response = curl_exec($ch);
curl_close($ch);
echo $response;
```

</CodeGroup>

## Respuestas de error

| Estado | Significado | Causa habitual |
|---|---|---|
| `401 Unauthorized` | La solicitud no llevaba una clave válida. | Falta la cabecera, la clave está mal escrita, fue revocada o venció. |
| `403 Forbidden` | La clave es válida pero la cuenta no puede hacer la acción. | La cuenta está suspendida. |

Todos los fallos de autenticación devuelven el mismo cuerpo `401`, de modo que el error nunca revela si una clave existe:

```json 401 Unauthorized
{"status": "error", "detail": "unauthorized"}
```

```json 403 Forbidden
{"status": "error", "detail": "forbidden"}
```

<Tip>
  Conviene usar una clave por integración y por modo, así revocar una nunca interrumpe a las demás. Para rotar: crear la clave nueva, actualizar el gestor de secretos, confirmar que el tráfico fluye y recién ahí revocar la vieja.
</Tip>
