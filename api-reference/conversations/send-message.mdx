</Note>

Envía un mensaje a una conversación activa en nombre de una persona del equipo, sin intervención del agente de IA. Es la opción indicada cuando un vendedor necesita entrar en un momento crítico —una charla sobre financiación, una negociación de precio o el cierre de una operación— sin esperar a que la IA responda primero.

El envío es asíncrono. La API responde `202 Accepted` cuando el mensaje queda encolado hacia el canal, no cuando el destinatario lo recibe: la entrega se sigue después por el campo `status` del mensaje.

## Endpoint

```text
POST https://platform-api.deltalead.ai/v1/conversations/{id}/messages
```

## Parámetros de ruta

<ParamField path="id" type="string" required>
  Identificador único de la conversación a la que se envía el mensaje, por ejemplo `conv_xyz789`. La conversación no puede estar en estado `resolved`.
</ParamField>

## Cuerpo de la solicitud

<ParamField body="body" type="string" required>
  Cuerpo de texto del mensaje. Debe ser una cadena no vacía, salvo cuando el mensaje lleva un adjunto. El formato Markdown no se renderiza en el dispositivo del destinatario: conviene enviar texto plano.
</ParamField>

<ParamField body="type" type="string" default="text">
  Tipo de mensaje. Valores aceptados: `text`, `image`, `document`. El valor por defecto es `text`.
</ParamField>

<ParamField body="media_url" type="string">
  URL de acceso público del archivo que se adjunta. Es obligatoria cuando `type` es `image` o `document`, y se ignora cuando `type` es `text`.
</ParamField>

## Solicitud de ejemplo

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/conversations/conv_xyz789/messages \
  -H "Authorization: Bearer dl_live_..." \
  -H "Content-Type: application/json" \
  -d '{"body": "Hi María, I'\''m your sales advisor. Let me check the financing options for you."}'
```

## Respuesta

Una solicitud correcta devuelve `202 Accepted` con el mensaje ya creado y encolado. El mensaje nace con `status` en `queued`.

```json 202 Accepted
{
  "id": "msg_005",
  "conversation_id": "conv_xyz789",
  "direction": "outbound",
  "body": "Hi María, I'm your sales advisor. Let me check the financing options for you.",
  "type": "text",
  "media": [],
  "sender": "human",
  "ai_agent_id": null,
  "ai_agent_name": null,
  "status": "queued",
  "error_code": null,
  "received_at": null,
  "created_at": "2024-03-11T09:05:33Z",
  "updated_at": "2024-03-11T09:05:33Z"
}
```

### Campos de la respuesta

<ResponseField name="id" type="string">
  Identificador único del mensaje recién creado, con el prefijo `msg_`.
</ResponseField>

<ResponseField name="conversation_id" type="string">
  ID de la conversación a la que se envió el mensaje.
</ResponseField>

<ResponseField name="direction" type="string">
  Siempre `outbound` para los mensajes enviados por este endpoint.
</ResponseField>

<ResponseField name="body" type="string">
  El texto del mensaje tal como se envió.
</ResponseField>

<ResponseField name="type" type="string">
  Tipo de mensaje, según lo indicado en la solicitud. Uno de `text`, `image`, `document`.
</ResponseField>

<ResponseField name="media" type="array">
  Archivos adjuntos al mensaje. Es un arreglo vacío en los mensajes de texto.
</ResponseField>

<ResponseField name="sender" type="string">
  Siempre `human` para los mensajes enviados por este endpoint, lo que permite distinguirlos de los que genera el agente de IA dentro del historial.
</ResponseField>

<ResponseField name="ai_agent_id" type="string | null">
  Siempre `null` en los mensajes enviados por este endpoint.
</ResponseField>

<ResponseField name="ai_agent_name" type="string | null">
  Siempre `null` en los mensajes enviados por este endpoint.
</ResponseField>

<ResponseField name="status" type="string">
  Estado de entrega. Nace en `queued` y avanza a `sent`, `delivered` o `failed`.
</ResponseField>

<ResponseField name="error_code" type="string | null">
  Identificador del motivo de falla, en `snake_case`. Solo viene con valor cuando `status` es `failed`.
</ResponseField>

<ResponseField name="created_at" type="string">
  Marca de tiempo ISO 8601 del momento en que el mensaje se encoló.
</ResponseField>

<Note>
  `202 Accepted` confirma que DeltaLead aceptó el mensaje, no que el lead lo recibió. El canal puede rechazarlo después —por ejemplo, si la ventana de mensajería de WhatsApp está cerrada—, y en ese caso el mensaje queda en `failed` con un `error_code`. El estado final se consulta releyendo la conversación con [Obtener conversación](/api-reference/conversations/get).
</Note>

## Derivar la conversación a una persona

`handoff` saca la conversación de manos del agente de IA y la asigna a un vendedor. Mientras la conversación está en `handed_off`, el agente de IA deja de responder: contesta únicamente la persona asignada.

```text
POST https://platform-api.deltalead.ai/v1/conversations/{id}/handoff
```

<ParamField body="assignee" type="string">
  ID de la persona que queda a cargo. Si se omite, la conversación se asigna según las reglas de derivación de la organización.
</ParamField>

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/conversations/conv_xyz789/handoff \
  -H "Authorization: Bearer dl_live_..." \
  -H "Content-Type: application/json" \
  -d '{"assignee": "user_xyz789"}'
```

Devuelve `200 OK` con la conversación actualizada, sin el arreglo `messages`.

```json 200 OK
{
  "id": "conv_xyz789",
  "organization_id": "org_xyz789",
  "lead_id": "lead_abc123",
  "status": "handed_off",
  "assignee": "user_xyz789",
  "unread_count": 0,
  "last_inbound_at": "2024-03-11T09:04:58Z",
  "last_message_at": "2024-03-11T09:05:33Z"
}
```

## Resolver la conversación

`resolve` cierra la conversación: pasa a `resolved` y deja de aparecer entre los hilos que requieren atención. Un mensaje entrante posterior del lead la reabre en `open`.

```text
POST https://platform-api.deltalead.ai/v1/conversations/{id}/resolve
```

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/conversations/conv_xyz789/resolve \
  -H "Authorization: Bearer dl_live_..."
```

Devuelve `200 OK` con la conversación actualizada, en el mismo formato que `handoff`.

```json 200 OK
{
  "id": "conv_xyz789",
  "organization_id": "org_xyz789",
  "lead_id": "lead_abc123",
  "status": "resolved",
  "assignee": "user_xyz789",
  "unread_count": 0,
  "last_inbound_at": "2024-03-11T09:04:58Z",
  "last_message_at": "2024-03-11T09:05:33Z"
}
```
