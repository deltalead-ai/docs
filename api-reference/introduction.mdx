La API REST de DeltaLead da acceso programático de lectura a los leads de la organización. Sirve para construir integraciones a medida, alimentar reportes propios o sincronizar con sistemas que las integraciones nativas no cubren: un DMS propietario, un data warehouse interno o un CRM hecho a medida.

Para que un lead entre a DeltaLead desde un sistema propio se usa el [Custom Webhook](/api-reference/webhooks/custom-inbound), no esta API.

## URL base

Todas las solicitudes a la API se realizan sobre HTTPS contra la siguiente URL base:

```text
https://platform-api.deltalead.ai/v1
```

## Ejemplo rápido

La siguiente solicitud recupera los leads más recientes con `curl`. `YOUR_API_KEY` se reemplaza por la clave de API de la cuenta, que empieza con `dl_live_` o `dl_sandbox_`.

```bash
curl https://platform-api.deltalead.ai/v1/leads \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Formato de las respuestas

Todas las respuestas usan JSON. La API es de solo lectura en esta etapa: los endpoints disponibles son `GET`, así que no hace falta enviar `Content-Type` en ninguna solicitud.

Los datos de la persona viajan siempre dentro del objeto anidado `contact`, nunca en el nivel raíz del lead.

## Límites de tasa

El límite se aplica por clave de API: **5 solicitudes por segundo sostenidas**, con una **ráfaga de hasta 10**. Al superarlo, la API devuelve una respuesta `429 Too Many Requests` con la cabecera `Retry-After`, que indica cuántos segundos esperar antes de reintentar.

`Retry-After` es la única cabecera de recuperación que emite la API; no hay cabeceras de consumo restante. La [referencia de errores](/api-reference/errors) detalla el manejo completo de `429` y la estrategia de backoff exponencial.
