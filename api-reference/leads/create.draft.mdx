</Note>

Este endpoint crea un lead en DeltaLead sin que el contacto tenga que llegar por un canal conectado. Sirve para importar contactos desde una base heredada, enviar los envíos de un formulario propio o derivar leads desde una fuente de terceros sin integración nativa. El lead queda visible en el Inbox unificado apenas se crea.

## Endpoint

```text
POST https://platform-api.deltalead.ai/v1/leads
```

## Cuerpo de la solicitud

<ParamField body="contact" type="object" required>
  Datos de contacto de la persona. Es un objeto anidado: ni el nombre ni el teléfono se envían en el nivel raíz del lead.
</ParamField>

<ParamField body="contact.first_name" type="string">
  Nombre de pila.
</ParamField>

<ParamField body="contact.last_name" type="string">
  Apellido.
</ParamField>

<ParamField body="contact.email" type="string">
  Dirección de email.
</ParamField>

<ParamField body="contact.phone" type="string">
  Número de teléfono. Se recomienda el [formato E.164](https://en.wikipedia.org/wiki/E.164), por ejemplo `+5491155551234`.
</ParamField>

<ParamField body="contact.display_name" type="string">
  Nombre para mostrar. Si se omite, DeltaLead lo compone a partir de `first_name` y `last_name`.
</ParamField>

<ParamField body="status" type="string" default="new">
  Estado inicial del lead. Enum cerrado: `new`, `contacted`, `qualified`, `appointment`, `proposal`, `incubating`, `won`, `lost`.
</ParamField>

<ParamField body="score" type="integer">
  Score de calificación, entero de `0` a `100`. Si se omite, el lead queda sin calificación hasta que la IA lo evalúe.
</ParamField>

<ParamField body="interested_vehicles" type="array of string">
  IDs de vehículos del catálogo, no texto libre. Un vehículo que no está en el catálogo se carga primero ahí y después se referencia por su ID.
</ParamField>

<ParamField body="notes" type="array of object">
  Notas del lead. Cada elemento es un objeto y alcanza con `body`; el resto de los campos de la nota los completa DeltaLead.
</ParamField>

<ParamField body="notes[].body" type="string" required>
  Texto de la nota. Es visible para el equipo y nunca se le envía al lead.
</ParamField>

### Reglas de validación

Son dos, y son las únicas:

1. Al menos uno de `contact.first_name` o `contact.last_name`.
2. Al menos uno de `contact.email` o `contact.phone`.

Si falta cualquiera de las dos condiciones, la respuesta es `422` y ningún lead se crea.

## Ejemplo de solicitud

```bash cURL
curl -X POST https://platform-api.deltalead.ai/v1/leads \
  -H "Authorization: Bearer dl_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contact": {
      "first_name": "María",
      "last_name": "García",
      "email": "maria@example.com",
      "phone": "+5491155551234"
    },
    "status": "new",
    "score": 40,
    "interested_vehicles": ["veh_9f2c41"],
    "notes": [
      {"body": "Consultó por financiación a 36 cuotas."}
    ]
  }'
```

## Respuesta

Una solicitud exitosa devuelve HTTP `201 Created` con el lead recién creado. La descripción campo por campo está en [Obtener lead](/api-reference/leads/get).

Un lead creado por la API no tiene canal: `channels` queda vacío y se va llenando a medida que la persona conversa por WhatsApp, MercadoLibre, email u otro canal. `ai_summary_status` arranca en `not_requested`.

## Errores

<Accordion title="422 — Validación">
  Se devuelve cuando el cuerpo no cumple alguna de las dos reglas de validación. El arreglo `errors` indica qué campo falló.

  ```json 422 Unprocessable Entity
  {
    "status": "error",
    "detail": "validation_error",
    "errors": [
      {
        "field": "contact",
        "detail": "email_or_phone_required"
      }
    ]
  }
  ```

  Conviene ramificar por el identificador de `detail`, nunca por el texto. La lista completa de códigos está en [Errores](/api-reference/errors).
</Accordion>
