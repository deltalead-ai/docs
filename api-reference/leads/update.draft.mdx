<Note>
  La API REST está en acceso anticipado y se habilita por cuenta a pedido. Las claves de API no se emiten todavía desde el panel. Para solicitar acceso, contactar al ejecutivo de cuenta.
</Note>

Este endpoint actualiza uno o más campos de un lead existente sin sobrescribir el registro completo: avanzar el lead en el pipeline, asignarlo a un vendedor, corregir los datos de contacto o cambiar los vehículos de interés. La semántica es PATCH, así que alcanza con enviar los campos que cambian.

## Endpoint

```text
PATCH https://platform-api.deltalead.ai/v1/leads/{id}
```

## Parámetros de ruta

<ParamField path="id" type="string" required>
  Identificador único del lead a actualizar, por ejemplo `lead_abc123`.
</ParamField>

## Cuerpo de la solicitud

Todos los campos son opcionales y solo se modifican los que vienen en la solicitud. Los campos que no forman parte de esta lista se ignoran en silencio: la respuesta es `200` igual, pero el valor no se guarda.

<ParamField body="status" type="string">
  Nuevo estado del lead. Enum cerrado: `new`, `contacted`, `qualified`, `appointment`, `proposal`, `incubating`, `won`, `lost`.
</ParamField>

<ParamField body="contact" type="object">
  Datos de contacto: `first_name`, `last_name`, `email`, `phone`, `display_name`. Se combinan campo por campo, así que los que no se envían dentro de `contact` quedan como estaban.
</ParamField>

<ParamField body="tags" type="array of string">
  Etiquetas del lead. El arreglo reemplaza al anterior por completo.
</ParamField>

<ParamField body="assigned_to" type="string | null">
  ID del vendedor responsable del lead. Se pasa `null` para dejarlo sin asignar.
</ParamField>

<ParamField body="interested_vehicles" type="array of string">
  IDs de vehículos del catálogo. El arreglo reemplaza al anterior por completo. En la escritura son solo IDs, aunque el detalle del lead los devuelva enriquecidos.
</ParamField>

<ParamField body="channels" type="array of string">
  Canales asociados al lead: `whatsapp`, `mercadolibre`, `typeform`, `custom`, `manual`, `email`. El arreglo reemplaza al anterior por completo.
</ParamField>

<ParamField body="source" type="string">
  Etiqueta de origen del lead, por ejemplo `landing-page`.
</ParamField>

<ParamField body="score" type="integer">
  Score de calificación, entero de `0` a `100`. Un valor escrito por la API reemplaza al que haya calculado la IA.
</ParamField>

<ParamField body="internal_notes" type="string">
  Notas internas del equipo sobre el lead. Es un campo de escritura: no aparece en el lead que devuelven este endpoint ni [Obtener lead](/api-reference/leads/get).
</ParamField>

## Ejemplo de solicitud

Agendar una visita, asignar al vendedor y actualizar los vehículos de interés:

```bash cURL
curl -X PATCH https://platform-api.deltalead.ai/v1/leads/lead_abc123 \
  -H "Authorization: Bearer dl_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "appointment",
    "assigned_to": "user_xyz789",
    "tags": ["financiacion", "test-drive"],
    "interested_vehicles": ["veh_9f2c41", "veh_71ba08"]
  }'
```

## Respuesta

<Note>
  Solo se modifican los campos presentes en el cuerpo; los omitidos quedan exactamente como estaban. Los arreglos se reemplazan enteros, no se agregan elementos: para sumar una etiqueta hay que enviar la lista completa. Para vaciar un campo opcional como `assigned_to`, se lo pasa explícitamente como `null`.
</Note>
