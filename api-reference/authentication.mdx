Toda solicitud a la API de DeltaLead se autentica con una clave de API enviada como token Bearer en la cabecera `Authorization`. Las solicitudes que omiten la cabecera o envían una clave inválida se rechazan con una respuesta `401 Unauthorized` antes de cualquier procesamiento.

```text
Authorization: Bearer dl_live_...
```

Es el mismo modelo de clave que usa el [Custom Webhook](/api-reference/webhooks/custom-inbound): una sola emisión, rotación y revocación para toda la plataforma.

## Modos live y sandbox

El prefijo de la clave determina el modo, y nada más en la solicitud lo hace: no hay cabecera, parámetro ni host alternativo que lo cambie.

| Prefijo | Modo | Qué hace |
|---|---|---|
| `dl_live_` | live | Opera sobre los datos reales de la cuenta |
| `dl_sandbox_` | sandbox | Opera sobre datos de prueba, aislados de los de producción |

Enviar la clave de sandbox desde un entorno de producción es un error silencioso desde el punto de vista de la API: la solicitud es válida y responde `200`, pero escribe donde no corresponde. Conviene inyectar la clave por variable de entorno y no fijarla en el código.

## Gestionar las claves de API

Las claves se administran en **Organización → Integraciones → APIs y Webhooks → Custom Webhooks**. La pantalla está disponible en todos los planes; no hay ningún plan que habilite o limite las claves.

<Steps>
  <Step title="Abrir la pantalla de claves">
    Iniciar sesión en la cuenta de DeltaLead y abrir **Organización → Integraciones** en la barra lateral izquierda. Dentro del catálogo, la categoría es **APIs y Webhooks** y el ítem es **Custom Webhooks**.
  </Step>
  <Step title="Elegir el modo">
    La pantalla separa las claves en dos secciones: **API keys de producción** y **API keys de sandbox**. Cada clave se lista con su nombre, su identificador, su estado y su vencimiento.
  </Step>
  <Step title="Crear la clave">
    Al crear una clave se define un nombre descriptivo (por ejemplo, `Production – Zapier`) y un vencimiento: entre 1 y 365 días, o sin vencimiento. El valor completo se muestra **una sola vez**: hay que copiarlo de inmediato y guardarlo de forma segura. Una clave perdida no se recupera, se rota.
  </Step>
</Steps>

### Estados

| Estado | Significado |
|---|---|
| **Activa** | La clave autentica solicitudes con normalidad |
| **Vencida** | Se cumplió el plazo configurado al crearla y ya no autentica |
| **Revocada** | Se dio de baja manualmente y ya no autentica; la baja es inmediata y no se deshace |

### Acciones por clave

- **Renombrar** — cambia el nombre visible. No afecta al valor de la clave ni al tráfico en curso.
- **Rotar** — emite un valor nuevo para la misma entrada. Es la operación a usar ante una filtración o como higiene periódica.
- **Revocar** — anula la clave de forma permanente. Las solicitudes que la usen pasan a responder `401`.

<Warning>
  Una clave de API otorga acceso completo a los recursos de API de la cuenta. Nunca debe subirse al código fuente, pegarse en mensajes de chat ni guardarse en texto plano. Conviene usar variables de entorno o un gestor de secretos dedicado (como AWS Secrets Manager, HashiCorp Vault o Doppler) para inyectarla en tiempo de ejecución. Ante una clave comprometida, corresponde rotarla o revocarla de inmediato desde **Organización → Integraciones → Custom Webhooks**.
</Warning>

## Enviar la clave de API

La clave viaja en la cabecera `Authorization` en cada solicitud. Los ejemplos siguientes muestran la misma llamada `GET /leads` en tres entornos habituales.

<CodeGroup>

```bash cURL
curl https://platform-api.deltalead.ai/v1/leads \
  -H "Authorization: Bearer dl_live_abc123xyz"
```

```javascript Node.js
const response = await fetch('https://platform-api.deltalead.ai/v1/leads', {
  headers: {
    Authorization: `Bearer ${process.env.DELTALEAD_API_KEY}`
  }
});
const data = await response.json();
```

```python Python
import os
import requests

response = requests.get(
    'https://platform-api.deltalead.ai/v1/leads',
    headers={'Authorization': f"Bearer {os.environ['DELTALEAD_API_KEY']}"}
)
leads = response.json()
```

</CodeGroup>

## Errores de autenticación

La API devuelve los siguientes códigos de estado HTTP ante fallos de autenticación:

| Estado | Causa |
|---|---|
| `401 Unauthorized` | Falta la cabecera `Authorization`, está mal formada, o la clave es inválida, está vencida o revocada |
| `403 Forbidden` | La clave es válida pero la cuenta asociada está suspendida |

La forma del cuerpo de estas respuestas está descrita en la [referencia de errores](/api-reference/errors).

<Tip>
  Conviene mantener una clave por entorno y por integración: una `dl_sandbox_` para las pruebas automatizadas y una `dl_live_` por cada sistema que consume la API. Así se puede rotar la clave de una integración comprometida sin interrumpir a las demás. Un vencimiento acotado —90 días, por ejemplo— convierte la rotación en rutina en lugar de una respuesta a incidentes.
</Tip>
